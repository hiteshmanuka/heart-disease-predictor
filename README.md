# Heart Disease Predictor

A machine learning application that estimates the probability of heart disease from a patient's clinical measurements. The project covers the full workflow: data preprocessing, model comparison, model explainability with SHAP, a REST API for inference, and an interactive web interface.

> **Disclaimer:** This project is intended for educational and demonstration purposes only. It is not a medical device and must not be used for clinical diagnosis or treatment decisions. Always consult a qualified healthcare professional.

## Overview

The system is composed of three parts:

- **Training notebook** (`Model_Training.ipynb`): cleans the data, builds a preprocessing pipeline, trains and compares three classifiers, analyzes feature importance with SHAP, and exports the final artifacts.
- **Inference API** (`app.py`): a FastAPI service that loads the saved preprocessor and XGBoost model and exposes a `/predict` endpoint.
- **Web frontend** (`frontend.py`): a Streamlit application that collects patient details through a form and displays the predicted risk.

## Features

- End-to-end preprocessing pipeline built with scikit-learn (`ColumnTransformer`) covering imputation, scaling, and one-hot encoding
- Comparison of Logistic Regression, Random Forest, and XGBoost on a stratified hold-out set
- Model explainability using SHAP summary plots for both Random Forest and XGBoost
- Input validation through Pydantic models in the API
- Interactive Streamlit interface with clear high-risk and low-risk output
- Reproducible development environment through a VS Code Dev Container

## Dataset

The project uses the **UCI Heart Disease** dataset in CSV form (`heart_disease_uci.csv`), which combines patient records from multiple medical centers. The file is not committed to this repository. Download it and place it at:

```
data/heart_disease_uci.csv
```

### Input Features

| Feature    | Description                                                                  | Type        |
| ---------- | ---------------------------------------------------------------------------- | ----------- |
| `age`      | Age in years                                                                 | Numeric     |
| `sex`      | Sex of the patient (male or female)                                          | Binary      |
| `cp`       | Chest pain type (typical angina, atypical angina, non-anginal, asymptomatic) | Categorical |
| `trestbps` | Resting blood pressure (mm Hg)                                               | Numeric     |
| `chol`     | Serum cholesterol (mg/dl)                                                    | Numeric     |
| `fbs`      | Fasting blood sugar greater than 120 mg/dl (true or false)                   | Binary      |
| `restecg`  | Resting ECG result (normal, st-t abnormality, lv hypertrophy)                | Categorical |
| `thalch`   | Maximum heart rate achieved                                                  | Numeric     |
| `exang`    | Exercise-induced angina (true or false)                                      | Binary      |
| `oldpeak`  | ST depression induced by exercise relative to rest                           | Numeric     |
| `ca`       | Number of major vessels colored by fluoroscopy (0 to 3)                      | Numeric     |

### Target

The original `num` column (severity from 0 to 4) is converted to a binary label: `0` for no disease and `1` for disease present (any value greater than 0).

## Methodology

### Data Preparation

1. Drop the columns `id`, `dataset`, `thal`, and `slope`. The last two are removed because of a high proportion of missing values.
2. Convert the target to a binary label.
3. Treat cholesterol values of `0` as missing, since they are physiologically implausible.
4. Map `sex`, `fbs`, and `exang` to numeric binary values.
5. Split the data 80/20 into training (736 rows) and test (184 rows) sets, stratified on the target with `random_state=42`.

### Preprocessing Pipeline

| Column group | Columns                                              | Steps                                      |
| ------------ | ---------------------------------------------------- | ------------------------------------------ |
| Numeric      | `age`, `trestbps`, `chol`, `thalch`, `oldpeak`, `ca` | Median imputation, standard scaling        |
| Categorical  | `cp`, `restecg`                                      | Most-frequent imputation, one-hot encoding |
| Binary       | `sex`, `fbs`, `exang`                                | Most-frequent imputation                   |

The pipeline is fitted on the training set only and produces 16 model input features.

### Models

Three classifiers were trained and evaluated on the same split:

- Logistic Regression (`max_iter=1000`)
- Random Forest (`n_estimators=100`)
- XGBoost (`n_estimators=100`)

XGBoost achieved the best accuracy and was selected for deployment.

### Explainability

SHAP `TreeExplainer` summary plots are generated for the Random Forest and XGBoost models to show which features contribute most to predictions and in which direction.

## Model Performance

## Installation

### Prerequisites

- Python 3.12 (recommended)
- pip

### Setup

```bash
# Clone the repository
git clone https://github.com/<your-username>/heart-disease-predictor.git
cd heart-disease-predictor

# Create and activate a virtual environment
python -m venv .venv
source .venv/bin/activate        # On Windows: .venv\Scripts\activate

# Install dependencies
pip install -r requirements.txt
```

Place the dataset at `data/heart_disease_uci.csv` before training.

## Usage

### 1. Train the Model

Open `Model_Training.ipynb` in Jupyter or VS Code and run all cells. The final cell writes the following files to the `models/` directory:

- `models/preprocessor.pkl`
- `models/xgboost_model.pkl`

### 2. Start the API

```bash
uvicorn app:app --reload
```

The API is available at `http://127.0.0.1:8000`. Interactive documentation is served at `http://127.0.0.1:8000/docs`.

### 3. Start the Web Interface

In a second terminal:

```bash
streamlit run frontend.py
```

Open the URL printed by Streamlit (typically `http://localhost:8501`), enter the patient's details, and select **Predict Risk**.

> The frontend sends requests to `http://127.0.0.1:8000/predict`. Make sure the API is running first.

## API Reference

### `POST /predict`

Returns a heart disease prediction for a single patient.

**Request body**

```json
{
  "age": 63,
  "sex": "male",
  "cp": "asymptomatic",
  "trestbps": 145,
  "chol": 233,
  "fbs": "true",
  "restecg": "lv hypertrophy",
  "thalch": 150,
  "exang": "false",
  "oldpeak": 2.3,
  "ca": 0
}
```

**Field values**

| Field     | Accepted values                                                    |
| --------- | ------------------------------------------------------------------ |
| `sex`     | `male`, `female`                                                   |
| `cp`      | `typical angina`, `atypical angina`, `non-anginal`, `asymptomatic` |
| `fbs`     | `true`, `false`                                                    |
| `restecg` | `normal`, `st-t abnormality`, `lv hypertrophy`                     |
| `exang`   | `true`, `false`                                                    |

**Successful response (200)**

```json
{
  "prediction": 1,
  "disease_detected": true,
  "probability": 0.8731,
  "risk_level": "High"
}
```

| Field              | Description                                                   |
| ------------------ | ------------------------------------------------------------- |
| `prediction`       | Predicted class (`1` disease, `0` no disease)                 |
| `disease_detected` | Boolean form of the prediction                                |
| `probability`      | Predicted probability of heart disease, rounded to 4 decimals |
| `risk_level`       | `High` if probability is greater than 0.5, otherwise `Low`    |

**Error response (400)**

Returned with a `detail` message when the input cannot be processed.

**Example with curl**

```bash
curl -X POST http://127.0.0.1:8000/predict \
  -H "Content-Type: application/json" \
  -d '{"age":63,"sex":"male","cp":"asymptomatic","trestbps":145,"chol":233,"fbs":"true","restecg":"lv hypertrophy","thalch":150,"exang":"false","oldpeak":2.3,"ca":0}'
```

## Development Container

- VS Code extensions: Python and Jupyter

To use it, open the repository in VS Code and select **Reopen in Container**.

## Limitations

- The dataset is small (920 records), so reported metrics carry meaningful variance and should not be treated as clinical performance.
- Evaluation uses a single train/test split without cross-validation or hyperparameter tuning.
- The `thal` and `slope` features were excluded because of missing data, which may reduce predictive power.
- The dataset originates from a limited set of institutions and may not generalize to other populations.
- The model produces a probability estimate, not a diagnosis.
